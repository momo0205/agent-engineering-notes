# Jev 无文本决策模型研究专题设计

日期：2026-09-20  
状态：待书面审阅  
目标站点：Agent 工程笔记

## 1. 背景与目标

Jev 是 TypeSafe AI 发布的决策模型。它接收非结构化状态与预定义问题，返回类型化选择、评分和概率，而不是生成自由文本。这个接口对 Agent Runtime 很有吸引力：许多运行时节点只需要一个可执行决策，不需要面向人的长篇回答。

本专题不把 Jev 当作已经成熟的技术结论，也不复述厂商营销。它要建立一个持续更新的公开研究档案，同时提供可执行教程和可复现实验，帮助读者回答以下问题：

- 去掉自由文本输出后，模型是否仍然拥有足够的内部计算能力；
- 输入上下文、内部表征、可见 Chain-of-Thought 和最终输出文本分别承担什么作用；
- 类型安全、概率校准与最终决策正确性之间有什么差距；
- `193.6×`、`444.6×` 和 `67.8%` 等性能数字使用了什么口径；
- Jev 的架构、并行 sampler 和 RLCD 已公开了什么，哪些仍只是厂商声明；
- Jev 在 Agent Runtime 中适合替代哪些 LLM 判断，哪些不能替代；
- 如何通过本地对照实验形成自己的结论。

成功标准不是“会调用一次 Jev API”，而是读者能够解释 Jev 的能力边界，运行对照实验，并用数据判断一个真实运行时决策节点是否值得接入 Jev。

## 2. 产品定位

专题采用“公开的进行中研究档案 + 实践实验教程”双轨结构。

研究线负责：

- 追踪官方事实、厂商声明和第三方证据；
- 解释目前能够得出的结论及其适用范围；
- 公开未解决问题和被推翻的假设；
- 审计性能数字和 benchmark 方法。

实践线负责：

- 教读者申请并安全配置 API Key；
- 运行 Choice、Score、Noul 的最小示例；
- 设计原子问题、阈值、拒答和人工复核；
- 建立规则、DeepSeek 与 Jev 的三方对照实验；
- 从离线评测逐步进入 Shadow Mode。

初版允许明确显示“研究中”“实验尚未开始”和“证据不足”，不为了页面完整而预填结论。

## 3. 证据模型

每个重要结论必须对应以下证据状态之一：

| 状态 | 含义 |
| --- | --- |
| 官方事实 | 官方文档、API 或 SDK 可以直接确认 |
| 厂商声明 | TypeSafe 已声明，但尚未独立验证 |
| 第三方观察 | 存在外部测试，但条件或复现仍有限 |
| 本地复现 | 使用固定代码、数据和版本得到的结果 |
| 暂时判断 | 根据当前证据做出的解释，仍可能修正 |
| 未解决 | 公开资料或实验暂时不足以回答 |
| 已推翻 | 后续证据否定了早期假设或结论 |

专题首页展示证据统计、最近审阅日期、已完成实验数量和未解决问题数量。每篇章节显示：

- 研究状态；
- 证据级别；
- 最近审阅日期；
- 依赖的模型或 API 版本；
- 是否经过本地实验；
- 结论适用范围。

性能声明统一使用三层表达：

1. 原始声明；
2. 计算口径；
3. 当前判断。

旧结论不得被新正文静默覆盖。发生修正时，应在研究日志中记录变化及原因。

## 4. 首发内容

第一版发布六个章节。

### 4.1 为什么研究 Jev

从运行时系统的真实需求进入：系统究竟需要可执行决策，还是需要可见的推理文本。列出核心问题、当前判断、专题边界和推荐阅读顺序。

### 4.2 Jev 是什么，不是什么

解释 System One、Choice、Score、Noul 和类型化概率输出；对比规则系统、传统分类器、Embedding、Reward Model 和生成式 LLM。强调 “System One Model” 是 TypeSafe 的产品分类，不是已形成学术共识的通用类别。

### 4.3 没有文本，它还在“思考”吗

严格区分：

- 输入上下文；
- 模型内部表征与计算；
- 对外可见的 Chain-of-Thought；
- 最终自由文本输出。

本章不把“不输出推理文本”写成“模型内部没有计算”，也不把 Jev 的出现写成“语言推理已经不重要”。对于未公开架构，只陈述可验证接口和厂商披露，不补造内部机制。

### 4.4 审计 193.6×、444.6× 与 67.8%

保存公开表格、原始来源、计算公式和对照关系，重点说明：

- 两个最高倍数来自不同的有利对照对象；
- `67.8%` 使用模型构造的参考判断，不等同于人工真值准确率；
- `production-style workflow` 是模拟完整工作流，不等同于真实生产流量；
- 官方评测能够支持的结论与不能支持的结论。

### 4.5 从零开始调用 Jev

覆盖 TypeSafe 官方 API 与 Vercel AI Gateway 两种获取路径，说明早期访问和网关差异。教程包含：

- API Key 申请；
- 本地环境变量配置；
- Python 环境；
- 第一次 Choice、Score、Noul 调用；
- 超时、限额和错误处理；
- 密钥扫描和公开仓库安全边界。

没有 API Key 时，页面仍可阅读接口和实验设计，但不得声称调用成功。

### 4.6 我们准备怎样验证它

定义规则、DeepSeek 结构化输出和 Jev 三方基线，说明数据集、标注、指标、Shadow Mode、失败案例记录和完成标准。第一版明确显示“实验尚未开始”。

## 7. 网站与实验台边界

网站仓库承载脱敏后的研究文章、教程、实验设计、固定版本引用和报告摘要。Python 实验台独立存在，不嵌入网站构建过程。

第一版实验台预期包含：

```text
providers/
├── rules.py
├── deepseek.py
└── jev.py

datasets/
runner/
metrics/
reports/
tests/
```

分离的目的：

- 网站不依赖 Python 和模型 API 才能构建；
- API Key、原始请求和私有数据不会进入公开内容；
- 实验代码可以固定 commit；
- 网站结论能够引用可追溯的实验版本；
- 后续可以独立演进 Java 接入。

## 8. 第一轮实验设计

第一轮选择有限答案空间、可以人工标注的 Agent 任务路由：

```text
search
code
database
human_review
```

每条样本记录：

- `sample_id`；
- 脱敏输入；
- 人工标签；
- 各方案输出；
- 选项概率与置信度；
- 延迟；
- 估算成本；
- 是否进入人工复核；
- 错误类型。

评估指标包括：

- accuracy；
- confusion matrix；
- precision / recall；
- Brier Score；
- calibration curve；
- P50 / P95 延迟；
- 单样本成本；
- 低置信度拒答后的 coverage；
- 不同错误的业务影响。

实验按以下阶段推进：

```text
离线固定数据集
→ Shadow Mode，只记录不执行
→ 仅为高置信、低风险决策开放自动执行
```

## 9. 运行时安全和回退

- Jev 超时或不可用时回退现有流程；
- 置信度不足时进入人工复核或更强的生成式 LLM；
- 答案空间保留 `unknown` 或 `human_review`；
- 模型版本变化后重新运行完整评测；
- 数据分布变化后停止沿用旧阈值；
- 规则可以确定的任务优先使用确定性代码；
- 高风险动作不由 Jev 单独批准；
- 原始输入不得包含未授权公开的公司数据、个人信息或凭据。

## 10. 内容边界

第一版不做以下事情：

- 猜测没有公开证据支持的模型架构；
- 虚构 RLCD 的数学细节；
- 发布尚未运行的实验结果；
- 把官方 benchmark 写成独立验证；
- 宣称“零幻觉”或“绝对可靠”；
- 直接控制 Agent Evidence Lab 或交易策略；
- 发布真实 API Key、内部数据或原始敏感输入；
- 提供尚未验证的 Java SDK 教程。

## 11. 测试与验收

第一版专题至少验证：

- 六个章节均有稳定路由；
- 章节前后导航正确；
- 每章都有研究状态和证据等级；
- benchmark 审计包含原始声明、计算口径和限制；
- quickstart 不包含真实 API Key；
- 尚未运行的实验明确标记为待执行；
- 不出现把厂商声明写成本地结论的措辞；
- sitemap、站内链接、生产构建和敏感内容扫描通过；
- 桌面与移动端保持现有站点的阅读体验。

## 12. 交付顺序

1. 建立 Jev 专题首页和六个首发章节；
2. 发布明确标记为进行中的第一版；
3. 教用户申请 API Key 并完成最小真实调用；
4. 建立独立 Python 实验台；
5. 运行规则、DeepSeek、Jev 三方离线对照；
6. 将脱敏后的结果和失败案例沉淀回专题；
7. 再决定是否进入真实项目 Shadow Mode；
8. 验证价值后再设计 Java 接入。
